# 局域网 HTTPS 与设备验收

TempShare 在私有 IPv4 网络中运行。不同私有子网可以通过路由器通信，前提是路由器允许设备互访。HTTPS 用本机管理的证书加密浏览器请求并验证服务器身份，开启后可以保存设备信任。HTTP 模式仍可在受信任的局域网使用。

## 证书和启动

1. 使用组织现有的局域网 CA 签发服务端证书，或使用本机 OpenSSL 生成并由自有 CA 签发。证书的 SAN 包含桌面显示的私有 IPv4 地址。使用屏幕投递时同时加入 `127.0.0.1`。IP 变化后重新签发含新地址的证书。
2. 核对 CA 证书指纹，通过可信渠道安装其公开证书。Windows 和 macOS 使用系统证书信任设置，iOS 安装配置后还需在「证书信任设置」中启用信任，Android 的入口根据系统版本和组织策略而异。服务端与 CA 的私钥留在各自的签发或运行环境。
3. 使用 OpenSSL 3 构建并启动。证书和私钥应为 PEM，私钥应仅当地用户可读取。Windows 双击启动时，参数错误通过图形对话框显示。

```sh
cmake -S . -B build -DTEMPSHARE_TLS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
./build/tempshare --cert /path/to/server-chain.pem --key /path/to/server-key.pem
```

用受信任的 CA 文件在桌面先验证服务。把下例的地址替换成界面显示的 HTTPS 地址。

```sh
curl --cacert /path/to/lan-ca.pem https://192.168.1.20:8787/api/health
```

## 本地故障定位

| 现象 | 检查 |
| --- | --- |
| 桌面没有可用局域网地址 | 检查电脑是否已接入私有 IPv4 网络并启用了网卡。169.254 开头的自动地址不能用于连接手机。 |
| 手机打开地址超时 | 使用桌面当前显示的地址和 TCP 端口。确认电脑接入可访问的私有网络，路由器允许设备互访，访客隔离已关闭。检查入站防火墙。设备发现使用 UDP 47871。 |
| 手机或控制台提示证书错误 | 检查客户端是否信任 CA、目标 IP 是否在 SAN 中、设备时钟和证书有效期。 |
| 能收发文件却看不到投屏 | 检查桌面浏览器的系统录屏授权，以及网络是否允许本地 WebRTC 或 mDNS 通信。用两端浏览器诊断 ICE 候选、连接状态与丢包。 |
| Linux 无法选择文件 | 检查 Zenity 是否安装。可在设置页直接输入文件路径。 |

## 实机回归

- Windows 从资源管理器双击，确认仅显示 TempShare 窗口。启动无效证书或无效参数实例，确认图形错误提示。
- 用同一实体手机在 iOS Safari 或 Android Chrome 扫码，从桌面其他功能页批准。验证错码、取消、过期、同名和中文文件名。应用处于 200% DPI 和最小窗口时重复操作。
- 通过两台设备测试隐私 Wi-Fi、多个网卡以及访客隔离网络。验证地址切换、组播发现、回环控制台与屏幕权限。
- 测试浏览器后台、两个标签页、网络恢复、关闭主机、停止观看和系统音频。比较 HTTP 与 HTTPS 的行为，确认投递只在授权会话内存在。
- 发布包内检查二进制、项目与依赖许可证、运行库版本，验证无网络时可正常启动与使用本地功能。

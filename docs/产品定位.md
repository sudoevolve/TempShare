> 让附近的设备，即刻连接。

| 项目属性 | 定义                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------- |
| 项目名称 | TempShare                                                                                      |

# 01. 产品概述

## 1.1 产品定义

TempShare 是一款轻量级、跨平台的临时设备连接工具。

它让用户能够在附近的设备之间快速传递文件、同步文本与内容，以及投递实时屏幕画面。

用户不需要注册账号，不需要配置复杂的网络环境，也不要求每台设备都安装客户端。

只需打开桌面端，选择目标设备或扫描二维码，即可建立临时连接。

TempShare 将文件传输、内容同步和屏幕共享统一到一个简单的设备连接体验中。

**它不是另一个网盘，也不是另一个远程桌面，而是一个让设备之间随时建立连接、完成任务并结束连接的工具。**

## 1.2 产品愿景

让不同设备之间的连接变得像复制粘贴一样简单。

无论用户正在使用电脑、手机还是平板，都应该能够自然地把内容发送到另一台设备，而不必考虑设备品牌、操作系统、账号体系或复杂的网络配置。

TempShare 希望成为设备之间最轻量的临时连接层。

## 1.3 核心价值

- **即时连接：** 发现附近设备，快速建立连接。
- **无需安装：** 手机和平板可以通过浏览器直接参与。
- **内容自由：** 文件、文本、图片和实时画面统一传递。
- **局域网直连：** 设备发现、配对和传输都在同一局域网内完成。
- **隐私可控：** 每次连接具有明确的授权范围和生命周期。
- **轻量运行：** 不常驻复杂后台，不引入不必要的资源消耗。

# 02. 用户痛点

现有跨设备工具通常围绕单一功能构建，用户需要根据任务选择不同的软件。

| 用户需求         | 常见解决方式           | 存在的问题                         |
| ---------------- | ---------------------- | ---------------------------------- |
| 手机向电脑传文件 | 数据线、网盘、聊天软件 | 步骤多、速度受限、文件可能经过云端 |
| 电脑向手机传图片 | 云盘、即时通讯         | 需要上传下载，操作不够直接         |
| 两台电脑传递文本 | 剪贴板工具、聊天软件   | 需要额外配置或安装                 |
| 手机查看电脑屏幕 | 远程桌面、直播工具     | 功能复杂，使用成本较高             |
| 临时连接陌生设备 | 账号配对、安装客户端   | 配置成本高，不适合一次性使用       |

## 2.1 核心问题

**设备之间缺少一种足够轻量、临时且通用的连接方式。**

用户真正需要的通常不是一个长期管理设备的系统，而是：

1. 找到目标设备。
2. 建立连接。
3. 完成内容传递。
4. 结束会话。

这个过程不应该被账号注册、设备配置、客户端安装和云端同步所干扰。

# 03. 产品定位

## 3.1 定位语

**TempShare：面向附近设备的轻量级临时连接与内容传递工具。**

英文定位：

*A lightweight, cross-platform tool for temporarily connecting nearby devices and sharing anything between them.*

## 3.2 产品差异化

TempShare 不以单一功能作为产品边界，而是以设备之间的临时连接为核心。

传统工具：

- 文件传输工具负责文件。
- 剪贴板工具负责文本。
- 远程桌面工具负责屏幕。
- 网盘负责长期存储。

TempShare：

- 一个入口。
- 一套设备身份体系。
- 一套连接与授权机制。
- 多种内容传递能力。

用户不需要理解不同工具的工作方式，只需要选择设备和要执行的操作。

## 3.3 产品核心竞争力

| 维度     | TempShare 的策略             |
| -------- | ---------------------------- |
| 使用门槛 | 扫码、自动发现、无需账号     |
| 接收端   | 浏览器优先，不强制安装客户端 |
| 功能整合 | 文件、文本、屏幕统一连接     |
| 网络模式 | 同一局域网直连               |
| 隐私     | 本地优先、临时授权、会话过期 |
| 产品体验 | 内容优先，而不是设备管理优先 |
| 运行成本 | 尽量不依赖中心化云服务       |

# 04. 目标用户

## 4.1 主要用户群体

### 个人跨设备用户

同时使用 Windows、macOS、Linux、iPhone 或 Android 的用户。

典型需求：

- 手机照片快速发送到电脑。
- 电脑文件直接发送到手机。
- 多台电脑之间交换文件。
- 手机向电脑发送链接和文本。

### 开发者与技术用户

经常在多台设备、虚拟机和开发环境之间切换的用户。

典型需求：

- 开发机之间传输构建产物。
- 手机向电脑发送代码片段或命令。
- 在不同系统之间交换日志和配置文件。
- 临时查看另一台设备的屏幕。

### 办公与协作用户

需要在个人电脑、会议设备和移动设备之间快速传递内容的用户。

典型需求：

- 临时投递演示文件。
- 手机向电脑发送现场拍摄的图片。
- 电脑向平板展示屏幕内容。
- 临时共享资料，不需要长期建立协作空间。

## 4.2 首要目标用户

第一阶段优先服务：

**拥有两台及以上设备、经常在不同操作系统之间传递内容的个人用户。**

他们能够直接感知设备连接成本，也更容易理解 TempShare 的价值。

# 05. 核心产品能力

TempShare 围绕三种核心能力展开：

1. Share：分享内容。
2. Sync：同步内容。
3. Cast：投递画面。

三种能力共用设备发现、身份验证、连接、授权和会话生命周期。

## 5.1 Share — 文件分享

<核心目标：让文件在设备之间自由流动。>

Share 是产品的基础能力，也是第一阶段的核心功能。

主要功能：

- 文件发送与接收。
- 多文件批量传输。
- 文件夹分享。
- 图片、视频和文档传输。
- 拖放文件即可发起分享。
- 浏览器端上传与下载。
- 传输进度、速度和剩余时间。
- 暂停、取消和失败重试。
- 文件接收目录设置。
- 文件名冲突处理。

核心体验：

用户在桌面端选择文件，或者直接拖入分享区域，即可创建分享会话。

接收设备通过二维码或附近设备列表加入会话，确认后开始传输。

文件不需要先上传到云端，也不需要经过第三方存储服务。

## 5.2 Sync — 内容同步

<核心目标：让设备之间的内容传递不再依赖聊天软件。>

Sync 负责文本和轻量内容的即时传递。

主要功能：

- 文本发送与接收。
- 链接分享。
- 图片发送。
- 代码片段传递。
- 桌面端主动剪贴板发送。
- 多设备之间的双向内容传递。
- 内容历史记录（可选）。
- 一键复制和快速粘贴。

核心体验：

用户复制一段文本，可以主动将其发送到指定设备。

接收设备直接展示内容，并支持一键复制。

产品不默认持续读取用户剪贴板。剪贴板同步必须由用户主动开启，并且具有清晰的授权提示。

## 5.3 Cast — 屏幕投递

<核心目标：让一台设备的屏幕可以被另一台设备即时观看。>

Cast 负责实时画面传递。

主要功能：

- 桌面屏幕共享。
- 指定窗口共享（平台支持时）。
- 浏览器观看屏幕。
- 移动端观看桌面画面。
- 画质与帧率调节。
- 网络状态自适应。
- 可选音频共享。
- 停止投递和会话管理。

核心体验：

桌面端开启 Cast，生成临时观看入口。

手机扫描二维码后即可在浏览器中观看画面，不需要安装远程桌面客户端。

Cast 第一阶段以单向观看为主，不把远程控制作为必要功能。

屏幕采集和播放能力受操作系统及浏览器权限限制，具体支持范围按平台逐步完善。

# 06. 设备连接体系

## 6.1 产品原则

**发现设备不等于信任设备，连接设备不等于允许所有操作。**

TempShare 需要同时满足连接便捷性和局域网安全性。

## 6.2 设备发现

客户端启动后，可以在用户允许的网络环境中发现附近运行 TempShare 的设备。

设备列表展示：

- 设备名称。
- 操作系统类型。
- 在线状态。
- 支持的功能。
- 信任状态。

设备发现不代表获得文件访问权限，也不应该自动接受文件。

## 6.3 设备信任等级

| 等级       | 定义                 | 行为                         |
| ---------- | -------------------- | ---------------------------- |
| 未配对设备 | 首次发现的设备       | 需要建立连接并确认           |
| 临时设备   | 仅参与当前会话       | 会话结束后授权失效           |
| 已配对设备 | 用户完成身份配对     | 可以快速发起连接             |
| 可信设备   | 用户主动授予更高信任 | 可以按照授权策略自动处理请求 |

可信设备的权限需要独立配置，不能默认拥有所有操作权限。

## 6.4 连接方式

### 附近设备连接

自动发现附近设备，用户选择目标设备并发起连接。

适合日常高频设备之间的传输。

### 二维码连接

桌面端生成二维码，手机扫描后直接进入网页会话。

适合首次连接、临时设备以及不方便安装客户端的场景。

### 手动连接

允许用户输入地址或连接码，作为自动发现失败时的备用方式。

## 6.5 授权机制

授权范围需要明确区分：

- 文件发送。
- 文件接收。
- 文本发送。
- 剪贴板操作。
- 屏幕观看。
- 音频共享。

用户可以针对不同设备设置不同的授权策略。

# 07. 产品形态与平台策略

## 7.1 桌面客户端

支持：

- Windows
- macOS
- Linux

桌面客户端是 TempShare 的主要运行载体，负责设备发现、会话管理、权限管理、文件收发以及屏幕投递。

桌面端提供完整功能。

## 7.2 移动端 Web

支持：

- iOS Safari
- Android Chrome
- 其他兼容的现代浏览器

移动端第一阶段不要求安装独立客户端。

通过扫描二维码或打开连接页面即可加入会话。

移动端 Web 主要提供：

- 文件上传与下载。
- 文本和链接发送。
- 图片发送与接收。
- 屏幕观看。
- 会话状态展示。

移动端浏览器受到系统权限和后台运行策略限制，因此不承诺所有平台都具备完全一致的能力。

特别是后台剪贴板同步和手机屏幕投递，需要根据具体系统和浏览器支持情况逐步实现。

## 7.3 桌面端之间

两台桌面设备均安装客户端时，可以获得更完整的连接体验：

- 自动发现。
- 快速传输。
- 双向内容同步。
- 屏幕投递。
- 设备配对。
- 信任管理。

# 08. 核心交互流程

## 8.1 手机向电脑发送文件

1. 电脑打开 TempShare。
2. 手机通过附近设备列表或二维码连接电脑。
3. 手机选择文件。
4. 电脑收到接收请求。
5. 用户确认接收。
6. 文件直接传输到指定目录。
7. 传输完成后，会话继续保留或按策略自动结束。

## 8.2 电脑向手机发送文件

1. 电脑拖入文件。
2. TempShare 创建分享会话。
3. 手机扫描二维码。
4. 浏览器展示待接收文件。
5. 用户确认下载。
6. 文件通过浏览器下载。
7. 会话按生命周期自动失效。

## 8.3 电脑向手机发送文本

1. 电脑选择文本或主动发送剪贴板内容。
2. 选择目标手机。
3. 手机收到内容。
4. 用户一键复制或打开链接。

## 8.4 手机观看电脑屏幕

1. 电脑开启 Cast。
2. 生成观看二维码。
3. 手机扫描二维码。
4. 浏览器申请必要权限并建立媒体连接。
5. 手机观看实时画面。
6. 电脑停止投递后，会话终止。

# 09. 安全与隐私定位

安全不是 TempShare 的附加功能，而是产品基础能力。

## 9.1 安全原则

- 设备发现、配对和传输均在同一局域网内完成。
- 设备发现与设备授权分离。
- 首次连接需要明确确认。
- 信任关系由用户主动建立。
- 每个会话具有独立授权范围。
- 临时连接具备有效期。
- 传输过程加密。
- 不自动执行接收的文件。
- 不默认读取剪贴板。
- 不默认开放屏幕或音频权限。

## 9.2 临时会话

每个连接都应具备独立的会话身份。

会话包含：

- 会话标识。
- 参与设备。
- 授权能力。
- 有效时间。
- 连接状态。
- 传输状态。

会话结束后撤销临时凭证，清理不再需要的临时资源。

## 9.3 隐私承诺

TempShare 的默认设计目标：

**用户的数据只在同一局域网内参与传输的设备之间流动。**

产品无需账号。设备发现、配对、传输和临时会话均由参与设备直接处理。

# 10. 产品边界

为了保持产品轻量，TempShare 不应该无限扩展为一个综合性平台。

## 10.1 暂不追求的功能

- 云盘和长期文件存储。
- 用户账号与社交关系体系。
- 多人在线协作文档。
- 完整远程桌面控制。
- 远程文件系统挂载。
- 企业级设备管理。
- 复杂的云端同步历史。
- 大规模团队协作空间。
- 跨公网连接、云端信令和中继。

## 10.2 明确的产品边界

TempShare 解决的是设备之间的即时连接与内容传递，而不是长期存储、团队管理或远程办公。

**连接是临时的，操作是明确的，内容由用户掌控。**

# 11. 竞品与差异化

TempShare 面对的不是单一竞品，而是多个细分工具。

| 产品         | 核心定位             | TempShare 的差异                               |
| ------------ | -------------------- | ---------------------------------------------- |
| LocalSend    | 局域网文件传输       | 扩展到文本同步和屏幕投递，强调统一临时会话     |
| KDE Connect  | 跨设备互联           | 浏览器参与、临时连接、轻量化                   |
| PairDrop     | 浏览器设备文件分享   | 增加原生桌面客户端、设备信任体系和更多内容能力 |
| AirDrop      | Apple 设备之间的分享 | 跨操作系统、浏览器接收                         |
| 远程桌面工具 | 远程控制与访问       | 聚焦轻量屏幕投递，不追求完整远控               |
| 网盘         | 云端存储与同步       | 同一局域网内临时直连                           |

## 11.1 核心差异

TempShare 不应该仅仅宣传自己支持更多功能。

真正的差异是：

1. **浏览器优先的接收体验：** 接收设备不一定需要安装客户端。
2. **统一临时连接：** 文件、文本和屏幕共享使用同一套会话体验。
3. **局域网直连：** 内容在同一局域网内直接传输。
4. **轻量化：** 不需要账号体系、云盘和复杂设备管理。
5. **可控信任：** 临时设备和可信设备拥有不同的授权策略。

# 12. 产品版本规划

产品采用渐进式开发策略，先验证最核心的使用场景，再扩展能力。

## V0.1 — Share

<badge color="success">首发版本</badge>

目标：打通跨设备文件传输的完整体验。

功能：

- 桌面客户端。
- 附近设备发现。
- 二维码连接。
- 手机浏览器接收端。
- 文件上传和下载。
- 多文件传输。
- 传输进度。
- 接收确认。
- 临时会话和自动过期。
- 基础设备配对。

第一阶段重点保证同一局域网内的稳定连接，不承诺任意网络环境下都可以直接连接。

## V0.2 — Sync

目标：让 TempShare 从文件传输工具变成内容传递工具。

功能：

- 文本传递。
- 链接传递。
- 图片传递。
- 桌面主动剪贴板发送。
- 双向内容传递。
- 快捷发送。
- 设备信任策略。

## V0.3 — Cast

目标：增加实时内容投递能力。

功能：

- 桌面屏幕捕获。
- 浏览器实时观看。
- WebRTC 媒体连接。
- 画质和帧率调节。
- 网络自适应。
- 可选音频传输。

## V0.4 — LAN Reliability

目标：改善同一局域网内的连接恢复和网络状态反馈。

功能：

- 网络变化检测与局域网地址更新。
- 同一局域网内断线重连。
- 发现失败和访客网络隔离提示。

# 13. 产品体验原则

TempShare 的设计应遵循以下原则：

### 13.1 内容优先

用户首先关心的是要发送什么，而不是设备之间的网络协议。

拖入文件、发送文本、开启屏幕共享，都应该成为明确而直接的操作。

### 13.2 临时优先

不要求用户长期维护连接关系。

一次性连接应该足够简单，常用设备则可以通过配对获得更快捷的体验。

### 13.3 默认安全

设备可以自动发现，但接收行为必须受到授权控制。

用户不应该因为连接了一个局域网，就默认信任所有设备。

### 13.4 尽量无感

不要求用户理解 IP 地址、端口、网络拓扑、传输协议等技术概念。

复杂性应该由产品内部处理。

### 13.5 克制而轻量

不引入不必要的账号、云存储、社交、广告和复杂后台服务。

每一项功能都应该围绕设备连接与内容传递展开。

# 14. 产品成功指标

TempShare 的成功不应仅以功能数量衡量，而应该以连接效率、传输可靠性和使用频率衡量。

| 指标           | 关注方向                           |
| -------------- | ---------------------------------- |
| 首次连接成功率 | 新用户是否能顺利建立连接           |
| 首次传输完成率 | 用户是否成功完成第一次传输         |
| 平均连接耗时   | 从发起连接到建立连接的时间         |
| 文件传输成功率 | 传输稳定性                         |
| 设备发现成功率 | 附近设备是否容易被找到             |
| 浏览器参与比例 | 无需安装客户端的使用价值           |
| 多设备使用率   | 是否真正解决跨设备问题             |
| 功能复用率     | 用户是否持续使用 Share、Sync、Cast |
| 资源占用       | CPU、内存、网络和后台资源消耗      |

最重要的初期指标：

**用户能否在第一次使用时，不看教程就把手机上的文件成功传到电脑。**

# 16. 最终产品定义

TempShare 的本质不是文件传输、剪贴板同步或屏幕共享中的任何一个。

它是一个面向个人多设备环境的轻量连接工具。

用户通过它发现设备、建立信任、创建会话，并在会话中自由传递内容。

文件可以被发送，文本可以被同步，屏幕可以被投递。

不需要账号，不需要复杂配置，不要求接收端安装完整客户端。

它不试图成为设备之间的另一个云平台，而是让设备在真正需要的时候连接起来，在任务完成之后自然结束连接。

**TempShare — Everything, temporarily connected.**

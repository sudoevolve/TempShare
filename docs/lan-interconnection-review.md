# 局域网电脑互联与 UI/UX 专项审查

审查日期：2026-11-27。基线：`127d6f2`（0.3.0），工作区起始干净。

范围：桌面发现、加入远端会话、配对、权限、多连接、文件和消息、双向投屏、生命周期、窗口布局、通知以及相关测试。本报告基于实际函数与调用关系；“确定”包括源码明确缺失的能力，不表示每项都在两台实体电脑上复现。前半部分保留0.3.0基线的问题证据与历史行号；0.4.0实施结果、验证边界见文末，不据此宣称已完成全 Wi-Fi/全浏览器验收。

清单共53项已确认的问题、功能缺口和交互改进项：High 12项、Medium 38项、Low 3项；另列6项需要实机验证的风险。相关问题按可独立验收的行为编号，部分共享同一个架构根因，不应把它们当成53个独立代码故障。

优先级：P0 为阻断电脑互联目标或导致用户非预期丢失会话/内容的问题；P1 为高频交互和可靠性问题；P2 为体验一致性问题。High / Medium / Low 表示影响严重程度。未发现足以列为 Critical 的问题证据。

## 实际连接路径与根因

```mermaid
flowchart LR
    A["电脑 A 桌面：本机 Session A"] -->|"连接附近电脑：open_url"| AB["A 上的浏览器"]
    AB -->|"HTTP 配对 / 上传 / 同步 / 观看"| B["电脑 B 桌面：Session B"]
    B -->|"本机 loopback 打开采集控制台"| BC["B 上的浏览器：屏幕采集"]
    BC -->|"WebRTC 或兼容 JPEG"| AB
    AB -. "没有同步加入状态" .-> A
```

1. 每个 C++ `Connection` 拥有本机 `Session + HttpServer + View`，是一个接待浏览器的服务槽位，不是到远端电脑的客户端连接。
2. `render_home/render_nearby` 的“连接”只调用 `open_url(peer.url())`，不建立远端会话对象，也不回写本机 `connections`。
3. `Session` 只有一个配对对象和一组固定的投屏 host/viewer 状态。`/cast` 与 host 授权限定 loopback；远端配对只授权 viewer。
4. 所以用户报告的“加入对方会话后，本机桌面没有会话、不能反向投屏”是当前模型的直接结果，不能靠修改按钮名称或开放远端 host 接口解决。loopback 限制原本承担采集控制的安全边界，不能直接删除。
5. 产品定位文档 `docs/产品定位.md:367` 声明桌面间提供自动发现、快速传输、双向内容同步、屏幕投递；当前实际体验没有将两边桌面纳入同一会话。

## 布局判断的证据边界

布局按实际逻辑像素计算，不能把物理DPI倍率直接乘进布局后声称最小宽度一定溢出。在860逻辑像素、连接栏可见时，主区实际为360；文件页主操作行的最后按钮结束于315，**这行本身没有越界证据**。确定的问题是状态驱动宽度突变，以及已配对后无法收起辅助栏。固定高度、长名称和DPI带来的具体裁剪属于R06的实机验收项；不同横向区域的控件处于相同y区间，也不足以证明它们直接覆盖。

## 推荐修复顺序与边界

1. **先定义同一个会话的两端。** 桌面无论创建还是加入，都显示同一个远端设备、当前角色、连接状态和可执行动作。创建/加入是连接建立方式，不应永久决定谁能发送屏幕。公共会话视图与网络实现分离。
2. **补齐角色和能力协议。** 明确文件发送、浏览下载、消息、发屏、收屏、方向切换及审批。支持一方请求更换投屏方向；保留本机采集的安全授权边界。
3. **修复生命周期。** 把暂时掉线、离开、断开设备、结束会话、删除内容拆开；明确到期和活跃任务处理；修正权限切换隐式删除消息。
4. **统一发现与接入。** 稳定设备ID、多地址聚合、设备级入口、忙碌状态和具体错误。多参与者接入属于协议/结构改动，需要先记录兼容方案，不能只把四个端口藏起来。
5. **重新整理任务界面。** 按当前设备组织“文件 / 消息 / 屏幕”，全局设置与会话权限分开；提供全局任务和待处理入口，窄窗口使用受约束布局。
6. **最后优化媒体与通知。** 先建立实际质量和失败原因指标，再调整编码、调度和降级；通知用稳定事件ID并覆盖加入方。
7. **验收后再宣布完成。** 至少验证A创建/B加入、B创建/A加入、同会话交换投屏方向、双向文本/图片/文件、双方断网恢复、到期/断开/退出以及第二台设备加入。Windows真实双机为第一轮；macOS/Linux不能以编译成功代替交互验收。

本轮验证：重新执行Windows Release配置现有CTest，2/2通过（share_roundtrip、desktop_gui_subsystem）。这只能作为接口与构建基线；本报告没有修改运行逻辑，也没有把上述问题标为已修复。

## 实施后的架构与取舍

`Session` 继续持有授权、共享清单、消息和任务；`HttpServer` 持有路由、原生连接桥和监听线程；`PeerLink` 持有对端地址、私密凭据、轮询及文件任务线程，寿命短于对应Session。UI只读取快照和调用显式动作，不持有远端密钥。关闭顺序先停止公共网关，再停止内部服务，路由引用不跨越服务寿命。

原生协议使用长度前缀字段并限制字段/响应大小；普通消息有序号避免回声，断连后轮换本机浏览器授权，旧连接响应通过generation和当前pair token隔离。接收方必须本机批准，不能因发起方声称已批准而自动放行。网关删除外来来源标头，用本次真实LAN端点转发；采集控制仍仅允许本机，不用放宽权限来实现反向投屏。

保留四个独立Session是兼容现有单设备授权模型的取舍，统一入口不意味着四台设备共享彼此的数据。转发文件使用流式处理，上传每块最多4MiB，避免网关把整份1GiB文件缓存在内存。原生状态每750ms轮询，最多4台时仍有重复序列化开销；如后续测量表明有瓶颈，可按revision增量拉取，避免未经测量更换整个通信栈。

没有新增运行时依赖。浏览器回归使用测试用 `playwright-core`，CI安装在运行器临时目录；仓库根目录不添加package.json、lock文件或额外cmake目录。Aino关闭补丁针对固定提交逐项匹配，匹配失败即停止配置；后续上游提供同等API后可移除补丁。
